# Decisions

Choices the brief leaves open, made so work could continue. Each can be revisited; change the entry rather than deleting it.

| # | Date | Decision | Why |
| --- | --- | --- | --- |
| D1 | 2026-10-07 | npm workspaces monorepo: `packages/core`, `packages/http-server`, `packages/stdio` (npm name `@billofladingdata/mcp`). Core and http-server are private. | Matches the brief's layout with the least tooling; no Turborepo/Nx needed at this size. |
| D2 | 2026-10-07 | TypeScript 6.0 (not 7.0). | `typescript-eslint` 8.x supports TypeScript < 6.1; the lint rule that blocks logging secrets depends on it. Revisit when typescript-eslint supports 7. |
| D3 | 2026-10-07 | Node 24 in CI (`.nvmrc`), `engines: >=22`. | 24 is the current LTS; 22 is still maintained and is what local containers ship. |
| D4 | 2026-10-07 | Zod 4, using its built-in `z.toJSONSchema`. | The brief asks for Zod schemas exported as JSON Schema; Zod 4 does this natively and the MCP SDK accepts Zod 4. |
| D5 | 2026-10-07 | Env var names: `BOLD_TEST_API_KEY` (tests, gate), `BOLD_API_KEY` (stdio), `BOLD_API_BASE_URL`, `BOLD_API_TIMEOUT_MS` (default 25 000). | Brief names the first two; the `BOLD_` prefix avoids clashing with generic names such as `API_TIMEOUT_MS`. |
| D6 | 2026-10-07 | Key-leak check reads the key from the environment / CI secret and searches for its first 8 characters in every tracked or untracked non-ignored file, plus all history in CI. It never prints the prefix. Without the secret (fork PRs) it is skipped; on pushes and same-repo PRs a missing secret fails CI. | The prefix cannot be committed to the repo without defeating the check. |
| D7 | 2026-10-07 | Fixtures: synthetic fixtures (shape from the brief) for all 22 paths now; `npm run fixtures:record` overwrites them with scrubbed staging responses in `test/fixtures/recorded/`, which take precedence. Free paths record by default; paid paths need `--paid`, unlocks need `--unlocks`, with a `--max-credits` cap (default 500). | Lets M0/M1 work proceed without a key while keeping live spending opt-in and bounded. |
| D8 | 2026-10-07 | Until a GitHub repo is available, work happens in a local git repo with a copy in the project's shared files (`bold-mcp/`). | No GitHub account was linked to the build session. |
| D9 | 2026-10-07 | M1 started while the M0 gate is blocked (no key in the build environment). M1 is built and tested against fixtures and a local mock API; its live checks run when the key arrives. | The job prompt says to build everything not blocked; the brief's "gate before next milestone" can't be met without the key. |
| D10 | 2026-10-07 | `@modelcontextprotocol/sdk` 1.32.1 (latest stable). It negotiates protocol 2025-11-25, 2025-06-18 and 2025-03-26; 2026-07-28 is not in any released SDK yet. A client asking for a newer version is answered with 2025-11-25. | The brief asks for the official SDK, latest stable. Upgrade when the SDK ships 2026-07-28. |
| D11 | 2026-10-07 | Streamable HTTP with stateful sessions (one McpServer per session, in memory per instance, bound to the key fingerprint or connection, 30-minute idle expiry). Multi-instance deploys need the load balancer to route on `Mcp-Session-Id`; an unknown session gets 404 and the client re-initialises. | Elicitation (M2 confirmations) needs the server to keep the request stream open across the client's reply. |
| D12 | 2026-10-07 | Header mode: a key the Partner API rejects still connects; tool calls return "API key not recognised — check the key in your client settings." A temporary API failure during validation counts as "unknown" for 30 seconds and calls go ahead. | Matches the brief's error table (tool error in header mode, HTTP 401 only for OAuth). |
| D13 | 2026-10-07 | Shapes not pinned down by the brief (list wrappers, top-10 rows, insight totals) are parsed tolerantly: rows from the first array in `data`, totals from `total`/`total_records`/`count`, nested rows flattened to scalars with the normalisation rules. Tighten to exact Zod schemas once fixtures are recorded. | Fixtures are synthetic until the key works. |
| D14 | 2026-10-07 | Top-up link in "not enough credits" errors is `https://billofladingdata.com` until the team gives a pricing/top-up URL. | Not in the brief. |
| D15 | 2026-10-07 | Page size caps for tokens: `search_products` 100, `find_company_id` and `find_company_contacts` 50, `get_credit_history` 250. Filter option lists capped at 100 items each. | Free tools still cost the AI client tokens; the brief only fixes caps for paid tools. |
| D16 | 2026-10-07 | Zod schemas live in `src/schemas/<tool>.ts` and tools in `src/tools/<tool>.ts`. | Follows the brief's layout; the "schemas with the tool" rule is kept by one schema file per tool. |
| D17 | 2026-10-07 | Upstream rate-limit "month" windows are 30 days. Per-connection and upstream limits use an in-memory store; Redis replaces it behind `RateLimitStore` in M3. | Calendar months need a store with calendar logic; 30 days is the conservative stand-in. |
| D18 | 2026-10-07 | The stdio package will be bundled (core inlined) before publishing in M5, since `@bold-mcp/core` is private. | Avoids publishing a second npm package. |
| D19 | 2026-10-07 | Protocol tests use the MCP Inspector CLI 2.9.0 with a config file (`scripts/inspector-check.mjs`) against the built stdio and HTTP servers and a local mock Partner API (`scripts/mock-partner-api.mjs`). | Inspector CLI ad-hoc targets need a writable catalog; a config file is deterministic in CI. |
| D20 | 2026-10-08 | Passing the connection's daily limit is a reason to ask (like the per-call limit), not a hard stop. Daily spend counts the server's estimated `credits_used`, all pools, per UTC day, per connection (key fingerprint in header mode). | The brief sets a daily limit but its "before each paid call" steps only describe asking; asking keeps the user in control. |
| D21 | 2026-10-08 | A `max_credits` argument lowers the per-call limit for that call; it never raises it. | The AI should not be able to lift the user's limit. |
| D22 | 2026-10-08 | Paid tools share one output shape: `status`, `pool`, credit fields and an optional `confirmation` object, with data fields optional (absent when confirmation is required). | MCP needs a single object `outputSchema`; a confirmation is a normal result (brief), not an error. |
| D23 | 2026-10-08 | Elicitation asks a yes/no form (`confirm: boolean`) with a 5-minute timeout; on decline the result is `status: "cancelled"`; if elicitation fails, the server falls back to a confirmation token. A call that already carries a `confirmation_token` is not asked again. | Brief step 4. |
| D24 | 2026-10-08 | After a call that charged credits, the pool balance is re-read from Credit Usage (fresh); otherwise the 60-second cache is used. An API 402 clears the cache. | `credits_remaining` must be current after spending. |
| D25 | 2026-10-08 | Charge estimates: per record = rows returned × price; Company Details and KYB Search = price once if anything is returned; Contacts Pro = 2 per non-empty page. | Brief: charged only when data is returned. |
| D26 | 2026-10-08 | Confirmation tokens are HS256 JWTs (`jose`) whose id is kept in a store until used. HTTP server reads the secret from `BOLD_CONFIRMATION_SECRET` (required in production, shared by all instances); stdio uses a random per-process secret. The memory store becomes Redis in M3. | Brief: signed, single-use, stored in Redis. |
| D27 | 2026-10-08 | Live smoke (`npm run smoke:live`) runs every tool once through the real server with page_size 1, confirms its own confirmations, and reconciles credits per pool against new Credit Usage Logs entries (newer than the entry seen before the run). CI runs the same script against a mock API that charges like the real one (`npm run smoke:mock`). | Brief's live smoke and the M2 gate "estimates match Credit Usage Logs". |
| D28 | 2026-10-08 | OAuth uses Express routes written for this server (not the SDK's `mcpAuthRouter`): RFC 9728 and RFC 8414 metadata, DCR, CIMD, `/authorize` with the connect page, `/token`, `/revoke`. Public clients only (`token_endpoint_auth_method: none`), PKCE S256 required, `resource` must be `<public URL>/mcp`, `iss` added to every authorization response. | The brief's paste-your-key page and key check sit inside the authorization step, which the SDK router's provider interface doesn't fit well. |
| D29 | 2026-10-08 | The connection is created when the code is exchanged, not when the key is pasted. Until then the encrypted key waits in the code record (Redis, 5 minutes, single use; a failed exchange also consumes the code). | An abandoned sign-in leaves nothing behind. |
| D30 | 2026-10-08 | CIMD documents are fetched with DNS pinned to the checked address (no rebinding), private/loopback/link-local/CGNAT/ULA addresses refused, no redirects, 5 s timeout, 64 KB cap, cached 10 minutes. | SSRF protection required by the brief. |
| D31 | 2026-10-08 | CSRF on the connect page: a random nonce in an HttpOnly `SameSite=Lax` cookie scoped to `/authorize`, and an HMAC form token bound to that nonce, the authorization request and its time (30 minutes). An expired page shows "This page expired. Paste your key again." | No scripts on the page, so a double-submit token is the simplest strong option. |
| D32 | 2026-10-08 | The 5-per-15-minutes key attempt limit counts every submitted key per client IP, valid or not. | Simple and errs on the side of stopping key guessing. |
| D33 | 2026-10-08 | Refresh-token reuse revokes the whole connection, and so do `/revoke` calls with either token type. A concurrent double refresh counts as reuse for the loser. | Brief: rotate refresh tokens and revoke on reuse. |
| D34 | 2026-10-08 | When the stored key is rejected by the Partner API (401), the connection is marked invalid and its access tokens stop working (HTTP 401 with the challenge), so the client signs in again. When KMS is down, `/mcp` answers 503 with `Retry-After: 30`. | Brief error table: OAuth key rejection is HTTP 401. |
| D35 | 2026-10-08 | Local stand-ins until the user provides accounts: `LocalKms` (AES-256-GCM key wrapping, master key from `BOLD_LOCAL_KMS_KEY`) behind the `Kms` interface, Postgres and Redis from `docker-compose.yml`. Without `DATABASE_URL`/`REDIS_URL` the server runs on in-memory stores with a warning (single instance, local only). A cloud KMS adapter is added once the hosting account exists. | Job prompt: stop and ask before needing a KMS key or cloud account. |
| D36 | 2026-10-08 | Connections unused for `BOLD_CONNECTION_IDLE_DAYS` (default 90) stop working at once and are revoked by `bold-mcp-admin expire-unused`, to be run daily by the host's scheduler. `bold-mcp-admin revoke-fingerprint <fp>` revokes every connection for a leaked key. | Brief: idle expiry and per-key revocation. |
